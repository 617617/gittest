Atomic push + closing

Forget-Safe Rule

The only command a human must remember
bk sync
  • Run at any time, in any state — never destructive.
  • Prints exactly one correct next action with a copy-pasteable ChatCommand.
  • If something is wrong: prints a FailureCode with full status fields, never half-applies a fix.
Three verbs the AI side may receive — humans never type these from memory
  • /bk work — normal start
  • /bk resume — same-holder recovery only
  • /bk takeover — cross-side from last pushed; requires yes, abandon

AI Chat Contract — Three Rules (v0.10)

Rule 1 · Self-announce

First non-empty reply line, before any tool call or repo read.

I am <CC|Codex>. Lane: <lane>.

Human matches against WindowMatch.

Rule 2 · Refuse wrong-window

If ChatTarget ≠ this chat:

  • Acknowledge wrong-window paste
  • Do not lease, edit, push, invoke skill
  • Reprint correct ChatTarget + ChatCommand

Rule 3 · Fixed closing

After one safe assignment, atomic push then end with exactly:

Done. Now run: bk sync

Byte-exact. No chaining to next package.

Gate Precedence — Consensus is Synthesis, Not a Bypass

1 · Lower gate

plan-audit / traceable review / package gate
  • BLOCK → planner repair or runner fix
  • PASS / accepted WARN → consensus may run

2 · Consensus

light · standard · full
  • plan default standard, synthesized by CC
  • code default light auto-accept on all-PASS, synthesized by Codex
  • Both AIs leave independent review opinions first

3 · Human accept_risk

last-resort override
  • May accept PASS or explicit WARN
  • Cannot override lower-gate BLOCK

Wrapper Boundary

bk.ps1 MAY
  • fetch remote refs
  • read BATON, progress, audit, review, consensus
  • acquire coordination lease (CAS)
  • call the correct Blue-K skill in the correct chat
  • publish one final handoff after a safe point
  • copy ChatCommand to clipboard (fail-soft)
  • print status dashboard via bk status
bk.ps1 MUST NOT
  • select packages
  • write progress tables
  • run stage-loop-auto or code-graph gates
  • create runner checkpoint commits
  • convert lower-gate BLOCK → PASS
  • merge, rebase, force-push, or auto-takeover across machines
  • ask the human to run raw git pull during normal operation

Lessons Learned — First Walkthrough

What broke and why

  • ContinueWithoutReview: yes was a misjudgment. CC authorized batch autopilot for speed; Codex pushed all 14 scenarios before per-step review could fire. This defeated the dual-AI peer-review value the test exists to provide.
  • The fix is enforced by default now: autopilot-decision.md ships with ContinueWithoutReview: no; Codex must observe review/<scenario>.md for scenario N before pushing scenario N+1.
  • Two Monitors are required, not one. Monitor #1 only watches test-results/; Monitor #2 watches the _coord/from-codex/ top level. Coordination questions (handoff-request-*, test-blocker-*) land on the top level — without Monitor #2 they slip past CC silently.
  • Headless codex.exe on this Windows host is access-denied from PowerShell. Unattended Mode B is therefore blocked until a standalone Codex CLI or a GitHub Action runner is set up. Tracked for v0.11 autonomy work, does not block v0.10 testing.
